NFTs

Why might some tokens be missing?

There's no standard function for "list every token ID in this collection" (BalanceOf tells you how many an address holds, not which ones) — this page probes sequential indices against the ID conventions we know about (this repo's own 1-based decimal, plain 0-based decimal, and gno.land/p/nt/seqid's 0-based compact encoding — the last one is common since seqid is a standard package), up to the collection's own TokenCount() if it exposes one, otherwise up to 60. A collection using some other ID scheme won't enumerate correctly here.

How are traits/attributes read?

Metadata is read via whichever of gno.land's two officially-sanctioned interfaces the collection implements: TokenURI() (a URI a client fetches/decodes — attributes come along for free, it's all one JSON blob) or TokenMetadata() (an on-chain struct, OpenSea schema). The on-chain path is trickier: a bare TokenMetadata() call renders its Attributes []Trait field as an opaque object reference, not the actual list — the chain's query interface doesn't expand nested list data in a plain function-call query. This page works around that by evaluating a small inline expression per attribute (indexing directly into the slice on the chain side and returning a plain string), which the same query interface renders normally. One accepted trade-off: trait type and value are combined as type=value in a single query to keep the request count down, so a value that itself contains "=" would split incorrectly — real trait values are simple labels in practice, so this hasn't been an issue.
